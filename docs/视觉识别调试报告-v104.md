# 掌中榫局视觉识别调试记录 v104

本次检查覆盖新手教程、榫卯解谜、机关修复与榫影成画，重点检查双手重叠和摄像头生命周期。所有测试均使用独立浏览器环境，不修改用户存档。

## 已修复的问题

1. **持续重叠裁掉露出的手指**：原逻辑将骨架外的像素全部裁掉，漏检手仅保留400毫秒。现在使用当前图像的肤色连通像素恢复可见部分，搜索范围受手部位置约束，连接腕部的手臂会被阻断；当区域泛洪到搜索边界时拒绝扩张，避免将同肤色身体整体纳入。恢复过程不读取目标图形。
2. **双手漏检后影形突然放大**：取消根据整个影形包围盒调节大小，改用掌宽与掌长估计距离；遮挡时冻结缩放，重新识别后平滑接管。屏幕显示和匹配使用同一个等比坐标变换。
3. **识别输入与显示裁切不一致**：模型与像素分离使用同一份冻结、镜像、4:3图像，避免定位到画面外的手或从下一帧背景采集肤色。
4. **轮廓修补关闭后影形消失**：基础手部颜色分离不再依赖修补开关，修补为0仍可识别。
5. **校准过早超时**：三个手势引擎统一从首个有效手部帧开始计时，摄像头授权、加载模型、等待手出现不再消耗校准时间，保留用户控制器与原阈值。
6. **教程断连后鼠标被锁住**：断开摄像头时清理持有、手部可见与旋转目标，释放鼠标交互并保留当前视角。
7. **异步旧会话影响新会话**：增加玩法三授权、播放、模型初始化和推理超时；旧会话结果及状态更新按会话编号隔离。

## 验证结果

- 持续4.5秒只返回一只手的定位结果、但图像中仍有双手露出部分：与双手定位参考影形的IoU约96%；从一开始就重叠、整体移动时约96%。测试图像包含与手掌连接的手臂。
- 另测±90°交叉、55°斜交和180°相向四种腕部姿态，当前检测手及连续2.5秒漏检手的已确认可见指尖均保留。历史指尖区域只用于允许像素连通，不用于绘制旧手形。
- 双手重新分开、另一只手移走：轮廓及时更新，移走后的影形与单手参考重合度超过99%。
- 同肤色身体背景：拒绝无边界的像素生长；完全丢手时不将身体作为通关影形。
- 关闭轮廓修补仍输出有效手影；保留明显指缝，未把分开的双手连接。
- 640×480分离处理在本机模拟测试的中位数约10毫秒、95分位约20毫秒；这是测试机数据，不代表所有手机性能。
- 十个手影关卡通过连续Canvas视频流→像素分离→匹配→奖励→重试的回归；这些图形视频用于检查软件链路，不能替代真实手势准确率统计。
- 本地MediaPipe双手模型能够初始化、接受裁切后的输入；空画面不计分，断开连接释放设备。
- 摄像头授权拒绝后重试、授权等待超时、迟到授权释放、运行资源失败后重试，以及手机横屏内嵌权限测试通过。
- 教程/玩法一/玩法二在8、15、30 FPS下通过个人校准、抓取、HOLD、重锚定与释放；无手等待80秒不提前进入默认阈值。
- 教程模拟已检测到手后断开摄像头，鼠标恢复旋转，页面无脚本异常。

## 验证边界

双手真实互相遮住的不可见部分不能从普通摄像头还原；同肤色身体与手完全没有可区分边界时，程序优先避免把身体纳入。此次可见轮廓恢复测试使用可重复的模拟图像及受控定位漏检，未采集用户本人的实时手势准确率，不能据此承诺任意光照、相机、距离和手势都能100%识别。旧版只检查400毫秒保留的测试不再作为持续重叠的通过依据。
